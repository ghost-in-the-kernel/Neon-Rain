### J-055 The flaky "survivors" of the mutation gate were a race in pytest's temporary folders (R-024 c)
- **Who:** Ghost, Claude Opus (reviewing), a fresh Claude Sonnet agent (under J-027).
- **Intent:** J-051 and J-053 each saw a mutant in an untouched file refused as a survivor and killed by a rerun with
  nothing changed (`scripts.checks.modules.x_file_problems__mutmut_31`, `scripts.checks.metrics.x_opened__mutmut_9`): find
  the cause and fix it without changing a test, a verdict or `neonrain/`.
- **Found:** Not the stats run: `mutmut-stats.json` came out identical in 6 runs, 3 of them under 8 busy loops. Not the
  cheapest-first order: 40 random orders of each named mutant's tests killed it every time. Not load by itself: 3 full runs
  under 8 and 3 busy loops and 40 reruns of one module's mutants were clean. Reproduced in 3 of 22 full runs (two beside a
  burner of pids, one on a quiet machine), the third time with a driver that logs the traceback of a child that raises:
  `mutmut results` said `timeout` (the gate prints any non-killed status as "unexplained survivor"), the exit code was 255,
  and mutmut maps 255 to "timeout" because it is what a child leaves when `pytest.main` raises. The exception was
  `FileNotFoundError: /tmp/pytest-of-root/pytest-current` out of `cleanup_dead_symlinks` in pytest's `pytest_sessionfinish`
  (`_pytest/pathlib.py`): the four workers keep their `tmp_path` folders under one `/tmp/pytest-of-<user>`, a worker starting
  unlinks and recreates `pytest-current`, and a worker finishing resolves that link in two steps, so it can find the link gone
  between them. The exception replaces the verdict whatever the tests said (the log shows the mutant's `F`). Only a mutant whose
  tests use `tmp_path` can be hit, which both named mutants' killers do. Without mutmut: 8 forked `pytest.main` sessions at a time on a test using `tmp_path`, 4 of 30,000
  raised; with a root of their own each, 0 of 30,000. Not seen: the stale-SIGXCPU-to-a-reused-pid hazard in mutmut's timeout
  thread (read in `workers/timeout.py`; it needs the pid space to wrap inside one mutant's wall limit, and 3 runs beside a
  pid burner logged none); recorded here as read, not as met.
- **Resolved:** `test/conftest.py` gives each mutant's pytest run a temporary root of its own (`PYTEST_DEBUG_TEMPROOT`, a
  new folder, removed when the run ends), under mutmut only; `test/test_mutant_tmp.py` holds it; `docs/MUTATION.md` says how to
  read a "timeout" on a millisecond mutant. Two full runs after it: all 4,459 verdicts identical to a run before it (4,442
  killed, the same 17 explained), 2.5 minutes each as before, no folder left in `/tmp`. On review, Opus gave
  `scripts/precommit.sh`'s four side-by-side slow-test sessions a temp root each too (the same race, with 4 sessions). Open: the
  gate still prints a timeout as a "survivor" (the status is in `mutmut results`); printing it is a small change for a tithe.
- **Touched:** test/conftest.py, test/test_mutant_tmp.py, docs/MUTATION.md, docs/journal/J-051-060.md, docs/journal/INDEX.md,
  docs/AGENT.md, docs/NAVIGATION-LOG.md.
